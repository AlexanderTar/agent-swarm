## P12 warning-data dependency

The review screen reads `warnings?: string[]` from `ArtifactResponse` returned by `GET /api/artifacts/{id}?revision={n}` and renders nonempty warnings above the plan markdown for `approve_plan` requests. `Review.test.tsx` proves that API shape through a response override. C2's plan-validation warnings are P12 backend work: the current `RegisterArtifactResult` and artifact GET payload do not store or return warnings, so a live plan review has no warnings to show yet. P12 must persist the warnings for the approved plan revision and add `warnings: string[]` to that artifact GET response; an empty array is suitable when the plan has none.
